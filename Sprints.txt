Sprint 1:

Objective: Set up a professional Django project with authentication and connect it to Supabase.

Sprint 1 Deliverables

By the end of Phase 1, I should be able to:

Clone your repository.
Install dependencies.
Run the server.
Register a user.
Login and receive a JWT.
View the authenticated user's profile.
Know that the data is stored in Supabase.

If all of that works, Phase 1 is complete.

Task 1 — Create the Project

Objective: Create a clean Django project.

Think before coding:

Should everything live in one app?

No.

Separate code by business domain.

For now I'd like to see something like

resort_backend/
│
├── config/
├── users/
│
├── manage.py

Notice we're not creating bookings, rooms, etc., yet.

Why?

Because we don't build features we aren't using yet.

Task 2 — Version Control

Before writing much code,

git init

Create a GitHub repository.

Commit after every meaningful milestone.

Example commits:

Initial Django project

Configured DRF

Connected Supabase

Created Custom User model

Implemented JWT authentication

This tells a story of your work.

Task 3 — Environment Variables

I don't want to see

DATABASE PASSWORD

SECRET KEY

JWT SECRET

hardcoded anywhere.

Ask yourself:

"If I upload this to GitHub today, would anything secret leak?"

If yes, rethink it.

Use a .env file and make sure it's ignored by Git.

Task 4 — Connect Supabase

Don't think of Supabase as "Supabase."

Think of it as

"Someone else's PostgreSQL server."

Your job is simply making Django talk to PostgreSQL.

Questions I'd expect you to answer:

Where do the credentials come from?
Which Django setting controls the database?
How do you know the connection actually works?

Hint:

If

python manage.py migrate

creates tables inside Supabase,

you're connected.

Task 5 — Install Only What We Need

Many interns install 30 packages.

Don't.

Ask yourself

"Am I using this today?"

For Sprint 1, you probably only need packages for:

Django
Django REST Framework
PostgreSQL driver
JWT
Environment variables

Nothing else.

Swagger can wait.

Image uploads can wait.

Payments can wait.

Task 6 — Custom User Model

This is where I want you to think.

Never start with Django's default User model unless you're absolutely sure you won't need changes.

Ask yourself:

Our resort needs

phone number
maybe nationality later
maybe passport number later

Can Django's default model handle that cleanly?

Probably not.

Research:

"How to create a custom user model in Django before first migration."

Notice the words before first migration.

That's important.

Task 7 — Authentication Flow

Don't think about JWT first.

Think like a customer.

Customer opens app.

↓

Registers.

↓

Logs in.

↓

Receives a token.

↓

Uses token to access protected routes.

↓

Logs out (client discards the token).

Now map those steps into APIs.

I'd expect endpoints roughly like

POST /register

POST /login

GET /profile

Keep them simple.

Task 8 — Permissions

Ask yourself

Should anyone be able to access

GET /profile

No.

Only the logged-in user.

So now you'll learn DRF permissions.

Task 9 — Test Everything

Don't assume.

Use Postman or Bruno.

Try:

✅ Register

✅ Login

✅ Copy token

✅ Call profile

Then intentionally break things.

Wrong password?

Expired token?

Missing token?

Duplicate email?

Those tests are just as valuable as the happy path.

Task 10 — Folder Organization

As we grow, I don't want a single 1000-line file.

Inside users, think about organizing code like:

users/

models.py

views.py

serializers.py

urls.py

permissions.py

tests.py

Even if some files are small initially, this separation will pay off as the project grows.

What I Expect You to Learn

Don't just finish tasks. By the end of this sprint, you should be able to explain:

Why use a custom user model?
Why JWT instead of sessions?
Why environment variables?
How Django communicates with PostgreSQL?
What DRF serializers do?
What authentication and permissions each handle?
Why authentication and authorization are different concepts?

If you can explain those in your own words, you've learned more than if you simply copied code.

Your First Assignment

Before writing any application logic, complete these steps:

Create the Django project and the users app.
Initialize Git and make your first commit.
Set up a .env file and configure environment variable loading.
Create a Supabase project and connect Django to its PostgreSQL database.
Run migrations successfully against Supabase.
Configure Django REST Framework.
Create a custom user model before creating any migrations.
Implement registration, login (JWT), and profile endpoints.
Test all endpoints using Postman or Bruno.

Once you've completed that, come back and tell me:

What went smoothly?
What was confusing?
Any errors you hit and how you resolved them.

Then we'll do a code review together and move on to Phase 2 (Rooms).
